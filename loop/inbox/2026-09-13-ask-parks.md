# Cursor agent model, slice 3 — PR #106, branch `cursor/ask-parks-b027` (on #104 → #98 → #92)

`ask` no longer blocks a turn. It parks:

1. `agents/<id>/waiting/ask-<call_id>.toml` is written (question, options, asked).
2. The turn writes the tool result, a `Waiting for your answer` notice, and ends (`turn_complete`, no interrupted line). The desktop card stays.
3. `Frame::Answer` (desktop card, `arbos-kernel answer`, phone) removes the file, writes the `answer` line, and drops an inbox file `kind = "answer"`, `reply_to = <ask id>` — the next turn starts from it.

`approve` still blocks; `waiting/approve-N.toml` mirrors it and goes with the decision.

## Scenario ideas

- **Restart while a question stands**: ask → kill the kernel → start it → answer from the card (or `arbos-kernel answer`) → a turn starts with the answer. Before, the question was orphaned.
- **Author the answer as a file**: write `agents/root/inbox/<stamp>-user-000.md` with `kind = "answer"`, `reply_to = "<id>"`, `wake = true`, and the body; remove `waiting/ask-<id>.toml` yourself or leave it (the kernel does not require the pairing — say if you think it should).
- **Two questions**: a model that asks twice in a row parks twice (two turns, two files). A blind answer (no id) is refused while two are pending; with the id it resolves the right one.
- **Skip**: the card's Skip sends an empty answer → the model is told the user skipped (from #95).
- **`--until-idle`**: exits with the "waiting" code while a parked question file exists.

## Known gaps

- The desktop shows the answer only as the model's next turn, not as a user bubble (same as before).
