## What shipped (slice 1)

- Gateway (`voice-server/`, branch `cursor/call-mode-narrator-cf3f` on `cursor/voice-server`): `session.start {mode:"call"}`; every utterance goes to the main agent as a `user` frame with `channel = "voice"`; a `Narrator` speaks highlights (turn end, sub-agent `done`, asks, failures; caps 240/200/160 chars; "the rest is on your screen"), never tool output; `more_detail` answers from the transcript via kernel `tail`/`read`; `narrator.say` frames for the client; `--call-model-voice off|ack|full` (default off: the narrator says "On it." and reads detail; the duplex model's own voice is cut). Deployed on the pod gateway (`/root/arbos-voice/src`, backup in `src.bak-pre-call-mode-*`).
- Kernel ([#99](https://github.com/unarbos/arbos/pull/99), integration base): `channel` (`voice` | `text`) and `device` (`phone` | `desktop` | `cli`) on `Frame::User` → the inbox file's front matter and the transcript's `user` line. A frame without a channel is `text`.
- Desktop ([#101](https://github.com/unarbos/arbos/pull/101), on #71): handset in the panel head (⇧⌘C), call strip under the composer (orb, live words, Mute ⇧⌘M, End), `voice ·` lines in the chat, a user card with a microphone for the caller's spoken words, driver `state.call` and `items[].channel`. The call names the tab `<machine>/<folder>`.
- Gateway ([#100](https://github.com/unarbos/arbos/pull/100)) also: hub attach per call (`session.start.project = machine/project` with `--hub`/`--hub-token`; `session.ready.via = hub`), `--highlights policy|model` (policy default; see `internal/call-mode-highlight-bench.md`).

## Where to try to break it

- Two utterances in quick succession (the second inside the 1.5 s forward grace): both must reach the agent, in order, `channel = "voice"`.
- A `more_detail` tool call that lands after the grace (slow model): the utterance reaches both the narrator and the agent; is the double answer bearable?
- A sub-agent `done` while the narrator is mid-sentence; three `done` files inside 3 s (coalescing: one line, "N agents finished").
- An `ask` frame during a call: the next utterance must be the answer (`answer` frame with the ask id), not a new request.
- Kernel restart mid-call: the gateway's kernel client does not reconnect (known); the call should end with an error line, not hang.
- Desktop: press Call twice fast; End while connecting; type during the call while muted; a second tab's Call while one is live.
- Barge-in during the narrator's own speech (not the model's): `interrupt` → the queued lines must be dropped, not spoken later.

## Safety (slice 3): the gateway never auto-approves

Any `allow …` ask from any kernel the gateway is attached to must be spoken and answered by the caller (yes/allow, no/deny), by a question card, or denied on `--approval-timeout`. Try: an approval while the caller is mid-sentence; "yes" said to a *question* (not an approval) — must be the answer text, not an approve; two approvals from two agents at once; an approval on a hub-attached kernel; `--auto-approve` must never touch a hub attach; a yes said after the timeout must be refused by the kernel (no pending question), not approve the next thing.

## More places to break it (slice 2)

- Two turns back to back (a typed line right behind a spoken one): both highlights must be spoken, in order (fixed once; regression-prone).
- A hub name the hub knows but whose kernel is down; the hub going away mid-call (the per-call attach has no reconnect).
- `--highlights model` with a slow or erroring OpenRouter: the policy line must be spoken within ~4 s, never both lines.
- A foreign user card marked voice while no call is live must not happen; a phone-typed line during a desktop call is the known mislabel.

## Known gaps (not bugs to file again)

- The NVIDIA duplex model rarely calls `more_detail`; drill-down then escalates to the main agent (one extra turn) — works, slower.
- Reconnect holds up to 64 frames while the link is down; a longer outage drops the rest with an error. The hub itself restarting is covered by the same path (the per-call attach reconnects to the hub URL).
