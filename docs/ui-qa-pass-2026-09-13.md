| `pr71-afa582a` | `cursor/window-layout-tabs-right-panel` (#71) | `afa582a` | tab bar on top, right panel |

Both were built with `cargo build` (kernel and `desktop/`), launched on the VM's Xvfb display `:1` (Xvfb = an X server that draws into memory, no monitor), light appearance, with an OpenRouter key from the Arbos 1Password vault and model `openai/gpt-5.4-mini`.

## Words used here

- **Driver socket**: a Unix socket the app opens when `ARBOS_DRIVER_SOCKET` is set. It takes JSON commands: `snapshot` (every element with its id, box, and whether it is clickable), `click`/`type`/`key`/`hover`/`drag`, and `state` (the app's own view of projects, sessions, composer, menus, windows).
- **Element id**: the name the app gives a control, such as `composer-send` or `tab-close-0`. The pass clicks by id, never by pixel.
- **State dump**: the JSON that `state` returns. Assertions read fields like `composer.text`, `active_session`, `panel_open`, `menu_open`, `opener_open`, `settings_open`, and per-session `streaming`/`turn_open`/`queued`/`questions`/`permission`/`pills`/`items`.
- **Result words**:
  - `pass` — the expected change showed up in the state dump (or in element geometry).
  - `fail` — the click was accepted but the state did not change as the PR or common sense says it should. Every `fail` is either a bug below or an explained branch difference.
  - `unverified` — the click was accepted, but the state dump has no field for what it should have changed (for example a Settings toggle). The still shows what happened; a human can judge.
  - `not-reachable` — the element was not on screen in that state, the model never produced the state (no permission prompt, no plan strip), or the driver cannot do it (native dialogs). Driver-caused cases are listed under **Driver gaps**.
  - `skipped` — deliberately not pressed: destructive (`key-forget`), opens a native file dialog (`composer-attach`, `config-reveal`), rewrites config for the rest of the run (`provider-*`), or opens the system browser (`commit`; verified once — Chrome opened).

`ui_pass.py` runs phases in this order, each one setting up the state it needs: **L** launch and inventory · **C** composer (field, model picker, `/` commands, mic, send, Local row) · **T** a long turn (Stop disc, queue rows, Interrupt now, stop word, footer copy/vote/fork/rewind, Worked fold) · **Q** question card (options, Other…, Continue, Skip) and a permission attempt · **P** plan strip · **S** sub-agents (inline child lines, panel rows, pills) · **A** artifact cards · **B** tab bar/opener (or sidebar) · **R** right panel and shortcuts · **W** settings window (every control in every section) · **M** menus · **O** a second launch with no kernel key (provider-offer strip). A full run took 7–9 minutes per branch. After each phase the rows and stills are copied to `media/qa-ui/<branch>/` (`results.json`, `inventory.json`, `NNN-<element>.png`).

Some rows were re-checked by hand with the same driver (the `1NN-v-*.png` stills; rows marked "manual" or "v-"). Three assertion mistakes found that way were corrected in the script and, where the Observed column says so, in the recorded rows. **[from memory]** The pass on `integration-67dcb85` was run three times that morning; the first run was aborted after a hung turn (see ui-004) and the second was superseded by the third after assertion fixes. ## Driver gaps

Things the driver (`desktop/src/driver.rs` + `arbosdriver.py`) cannot see or do today. Each one turned a check into `unverified`, `not-reachable`, or a workaround.

1. **No selection/toggle state for Settings controls.** `appearance-N`, `reduce-transparency`, `cursor-blink`, `bionic-reading`, `hue`, `intensity`, `size-up/down`, `watch-bounce-N`, `provider-N`, `model-pick-N` all clicked fine but nothing in `state` says what changed (only `text_size` exists). Most `unverified` rows come from this. Add a `settings` object to `state` (appearance, toggles, provider, key present, model).
2. **Question card selection is not exposed.** `state.sessions[].questions` is only the title; which option is selected, and whether Other… has text, is not readable. `ask-N-…` clicks are `unverified`.
3. **Fold state is not exposed.** `work-N`, `thought-N`, `tool-N`, `diff-card-N`, `term-card-N` have no expanded flag; the pass infers it from the footer moving. `tool-N`/`thought-N`/`diff-*`/`term-*` never appeared as elements in any run (the Worked fold expands to plain text).
4. **`screenshot` is macOS-only** (qa-015). The pass uses `scrot` on the X display instead, so stills are whole-screen, not per-window.
5. **Closing the Settings window through the driver drops the socket** (cmd-w sent to the settings window). The pass closes it with `wmctrl -c Settings` and reconnects. `use_window("settings")` itself works.
6. **Native dialogs are not drivable**: `composer-attach` (file picker), `config-reveal` (file manager), `commit` (browser). Skipped.
7. **Duplicate-looking ids**: `session-1` is both the row and the parent of `session-dots-1`, so the glob `session-[0-9]*` also matches `…session-1.session-dots-1`. Distinct id families (`session-row-N`) would make patterns safe.
8. **Menus have items but no menu identity**: `state.menu_open` is a bool; which menu (tab, session, header) and its item labels are not readable. Items are clickable (`session-menu-7-0..3`, `tab-menu-1-0..1`) but their text is unknown to the driver, so the pass did not press them (Delete/Archive are among them).
9. **Push-to-talk (Fn) and system-level keys** cannot be sent through `key`; the mic can only be clicked. The voice path is Linux-blocked anyway ("only works on this Mac").

## Re-running on every app change

- Build the branch, then `python3 internal/parity/ui_pass.py --branch <label> --binary … --kernel …`. Use `--phases LCT` for a 3-minute smoke pass (launch, composer, turn) or the full default `LCTQPSABRWMKO`.
- Diff `media/qa-ui/<label>/results.json` against the previous label: any row whose `result` moved away from `pass` is a regression; new ids in `inventory.json` are new controls to add checks for.
- The LLM makes some states nondeterministic (question card, plan strip, sub-agents, artifacts). The script records `not-reachable` with the reason when the model does not produce the state; re-run those phases (`--phases QPSA`) before calling a regression.
- Write any rewrite of this document to `/tmp` first and copy it in; the store must never hold the only copy.
