## Learned (2026-09-16)

- On OpenRouter, an account-level provider block (`openai/*` 403) is invisible to `/key` and `/models`; the only truthful probe is a call. Learn from refusals, remember them per API host, and probe once at kickoff (#298).
- A store-service fault can take a whole top-level directory of the Project store; the store is not a backup. Every document worth keeping should also live in a PR (this file's Shipped rows all do) — and a whole-file write goes to `/tmp` first, then a copy, so the old content survives until the new is durable.
- `cargo fmt --all` in the workspace root reformats files unrelated to the change; check `git status` before `git add -A` (it slipped a dozen desktop files into one commit once; reset and redone).
- Switching git branches while `cargo test` compiles in the same tree builds a mixed binary; run a full suite in a `git worktree` with its own `CARGO_TARGET_DIR`.
- The replay provider streams each reply as one delta; a `step` on `assistant_delta` and on the settled line is exact there and on the live providers alike.

## Learned (2026-09-15)

- A kernel's `tree` frame only lists live agents; anything the model must remember about finished workers has to be put back in front of it (`<<archived>>`, #287) or it says "none".
- A guard that judges one field teaches the model to drop the field. Judge the intent (the brief) and, where the fix is obvious, make it rather than refuse (#285).
- The same words twice is what the reader notices, not identical bytes: compare word overlap, not strings (#271).
- `background:true` is the one path that returns a `bash` call in half a second; a model marks a loop "long-running" and sets it (#244).
- On a router, 403 is usually one provider family blocked, not the key: fall through to the next model (#283).
## Learned (2026-09-13, remote batch)

- ArbosLife already runs the Go-era Arbos with `~/.config/arbos/{identity,secrets,settings.json}` and QA's loop uses `~/.cache/arbos`. Remote kernels therefore run with `XDG_CONFIG_HOME`/`XDG_CACHE_HOME` under the dedicated `/home/const/arbos-remote` so nothing of ours lands in the account's dot-folders.
- A kernel started in the background rewrites `kernel.json` a moment after start; a start script that reads the file must delete the stale one first, or a tunnel to a dead port looks like a link that "closed at once". The relay now also waits for the kernel's greeting frame before calling a link attached.
- `pkill -f '<pattern>'` from a shell whose own command line contains the pattern kills the shell. Use `[p]attern`. (Third time; now in the QA notes too.)

## Learned (2026-09-13, UI batch)

- Live emits and transcript lines share `Frame::Event`; only `seq` tells them apart, and it was not on the wire until #15. Any client that prints events (the parity suite included) needs that.
- The kernel says `Turn idle` on the done channel, but `turn_complete` arrives on the 200 ms tail tick — idle can precede the last lines. Clients must wait a grace period after idle.
- `pkill -f 'arbos-kernel serve'` from a shell whose own command line contains that string kills the shell. Use `pkill -f 'arbos-kernel [s]erve'`.
- Gemini 3.8 Flash on OpenRouter intermittently returns "Corrupted thought signature" mid-stream when `reasoning_details` are replayed; the kernel surfaces it as a failed notice and ends the turn. Not caused by any of these PRs; worth a fallback-model default (M-03).

## Learned
