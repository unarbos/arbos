## Required full implementation and concrete prerequisites

1. **Exporter/backend contract.** Owner supplies the existing OTLP-compatible destination/auth mechanism if one exists, otherwise recommended default is optional environment-configured OTLP export to a collector they own, disabled when absent. No new account, hard-coded endpoint/key or deployment is needed for a PR. Implement provider/exporter lifecycle, bounded batching/backpressure, shutdown flush and invalid-config behavior using Rust-version-compatible dependencies; pin/compile/test them. Current disk/CI blocker prevents claiming that implementation verified.
2. **Trace every requested definition.** Use definition-level instrumentation for handlers/middleware/helpers/request makers/exports. Rust `#[instrument(skip_all)]` plus explicit safe attributes is an appropriate native seam; do not auto-record structs/parameters. Retain core's no-I/O/platform-independent boundary and avoid dragging exporter runtimes into core/FFI just to annotate pure helpers. Trace spans can be lightweight behind the `tracing` facade, with exporter owned by executable entry points.
3. **AST-backed coverage check.** Inventory actual production definitions including impl methods, async-trait declarations/implementations, conditional features and route macros; explicitly distinguish cfg(test). Check permitted wrapper/annotation shapes and run against a deliberately untraced exported function negative control. A regex total, middleware-only check or excluded entire modules is not a passing exported-async lint. The repository currently has no such lint.
4. **Authenticated request context.** `relay/auth.rs:47–52` provides the authenticated user ID; project/chat/job/account IDs should follow actual authorized resource resolution. Failed authentication has no trusted user ID. Carry an explicit request context through handlers, spawned tasks, `spawn_blocking`, websocket rooms, Matrix jobs and subprocess/FFI edges. Context includes trace/span IDs, user/account/project/chat or job identifiers, operation name and terminal outcome/duration; use null/absent fields where a concept does not exist rather than fabricated user IDs.
5. **Safe propagation.** Parse incoming W3C headers, handle malformed/missing context deliberately, and inject child context at shared HTTP client request seams. Relevant seams: agentd Llm (`llm.rs:95–108,225–233`), stub proxy (`http.rs:325–342`), relay provider proxy (`proxy.rs:523–542`), Daytona (`daytona.rs:181–208`), LiveKit (`livekit.rs:169–183`), Matrix client wrappers, connectors, sidecar Relay (`relay.rs:83–116`), ACP posts (`main.rs:572+`), updater clients. Existing header allowlists must explicitly admit propagated context; do not forward every inbound header/baggage/auth to third parties. Cross-project `traceId` loop/rate guards are business routing metadata, not interchangeable trace context.
6. **Stream/job terminal ownership.** A handler may return response headers before the request's stream finishes. Relay proxy spawns the stream/meter at `proxy.rs:588–682`; request-send failures return early at `:542–545`, and client disconnect/stream-error currently end loops without a distinct terminal outcome in the completion record. Capture context into that owned task/body and emit exactly one final event for success/error/abort, with duration/TTFB/downstream status, without changing billing or stream semantics. Similar ownership applies to websocket connection lifetimes, background jobs, cancellation/retry and provider calls.
7. **One wide event + tail retention.** Define a bounded event accumulator and a single finalizer per request/job/attempt with correlation IDs, feature choices, durations, downstream summaries and safe typed error/outcome. Preserve high-cardinality identifiers as fields, not unbounded metric labels. Keep every error and slow event; sample only completed ordinary successes. Full distributed trace tail sampling requires a collector/buffering policy—head sampling cannot recover a slow/error trace already dropped. Do not invent a per-service sampling rate or collector limits without documenting the chosen operational contract.

## Material privacy/compatibility concerns at affected seams

- **Blanket argument instrumentation leaks credentials.** `relay/auth.rs:13–20` derives Debug for `Principal::Device` containing raw bearer `token`. Config/http-client/provider structs also own credentials and request bodies carry prompts/tool input. Default parameter recording must be disabled; safe allowlisted fields and typed errors only. Never log bodies/Authorization/keys/raw error response text.
- **Some upstream error strings already carry body text.** Llm errors include `v` (`agentd/llm.rs:110–117,235–237`); Daytona errors include clipped response text (`relay/daytona.rs:201–208`). Wide events must classify/redact at the source, not attach arbitrary Debug errors. Existing proxy `PromptShape` (`proxy_trace.rs:1–6,44+`) is an example of preserving useful shape without prompt contents.
- **Span-only account context will not reach current warning rings.** Both collectors ignore `Context` and record only Event fields. If an old event is moved under a user/account span and its explicit identifier is removed, per-account filtering can stop surfacing it. Safely inherit registered context into ring entries or preserve explicit identifiers; include isolation and scrub regressions.
- **Inspection redaction is not source/export redaction.** Rings scrub returned values and Store scrubs writes, while ordinary formatter sinks can still receive arbitrary event strings. Changing to JSON formatting alone does not fix this. Sidecar's line redactor and JSONL forbidden keys also are not a complete nested safe-event schema.
- **Feature and core boundaries matter.** `arbos-core` is no-I/O/no-Tokio shared code and bindings build across iOS/macOS/server targets. Central exporter dependencies belong in executable/runtime modules. A whole-workspace lockfile churn or uncompiled feature change is not safe evidence of full coverage.
