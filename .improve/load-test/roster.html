Chat roster batching

Fresh generated local databases and bundled SQLite 3.46.0. The original chat SELECT stays unchanged; one live-roster SELECT replaces one SELECT per chat. At 10,000 rooms, warm SQL p50 falls 84.308→27.615 ms, with 10,001→2 statements. Scope validation repeats in the batch query, increasing logical row visits 70,000→90,000. Both arms return the same 60,000 chat/member rows.

These are declared synthetic relationships: half DM rooms with 2 human owners, half groups with 7 humans and 1 agent,100 retained opaque rows per room, and one owner in every room. The largest database is 175.94 MB. These are SQL workloads; Rust roster allocation/DTO mapping, relay mutex waits, network and rendering are excluded. Complete list/detail DTO parity is checked separately by actual native regressions. No app-latency claim is made.

Each scale uses 101 randomized before/after pairs and 5 warmups per arm. Intervals are seeded 2,000-resample paired-median bootstrap intervals; p-values use an exact two-sided sign test excluding ties. One coordinated local run measures warm, readonly, single-reader behavior with scanstatus instrumentation. The baseline Cdriver copies chat IDs to execute its per-room queries; the batched arm consumes 2 SELECTs. Native mapping and concurrent writer latency are unmeasured. The new native method holds one connection lock through its two queries; the previous method reacquired it between per-room queries.

Full raw samples, fixture counts, exact SQL, source hashes and query plans are retained in ROSTER_RESULTS.json. Fresh databases are deleted after every scale; no existing database, hosted service or credentials are used.

Actual source queries

SELECT p.id, p.kind, p.created_by, p.created_at, p.title, p.image_key, p.avatar_leaf, p.avatar_leaf_color, p.description FROM people_chats p
                 JOIN people_members m ON m.chat_id = p.id
                 WHERE m.member = ?1 AND m.left_at IS NULL AND p.deleted_at IS NULL
                 ORDER BY p.created_at DESC

SELECT chat_id, member, role, added_by, joined_at, settings, muted, silenced, silenced_until FROM people_members WHERE chat_id = ?1 AND left_at IS NULL
                 ORDER BY joined_at, CASE WHEN member LIKE 'user:%' THEN 0 ELSE 1 END, member

SELECT chat_id, member, role, added_by, joined_at, settings, muted, silenced, silenced_until FROM people_members
                 WHERE left_at IS NULL AND chat_id IN (
                   SELECT p.id FROM people_chats p JOIN people_members m ON m.chat_id = p.id
                   WHERE m.member = ?1 AND m.left_at IS NULL AND p.deleted_at IS NULL
                 )
                 ORDER BY chat_id, joined_at, CASE WHEN member LIKE 'user:%' THEN 0 ELSE 1 END, member
