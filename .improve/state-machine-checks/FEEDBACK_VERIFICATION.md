# AUX-H6: feedback commit admission and delivery completion

The feedback controller has real persisted lifetimes across ticks. Two actual shared boundaries now make the critical transitions explicit: commit admission and delivery completion. The existing queued/running/gating/pushed dispatcher and scheduler remain in place; no duplicate orchestration model is introduced.

## Confirmed baseline behavior and changes

The prepared integration-tree path previously merged before reading member states. It now uses the same `admit_merge` / pure `commit_transition` boundary as the normal branch path, checking every member before the one tree merge effect. A valid member requires its documented per-item authorization, no operator hold, an eligible stage, a strictly boolean green verdict, its exact current branch head and actual ancestry in the CI-covered tree. Missing or invalid evidence holds. A global gate lift no longer releases a previously held item: the process contract explicitly requires per-item approval even after a lift. Human approval remains per-item; no SHA-scoped approval rule was invented. The gate and live-head identities remain SHA-bound. A deleted shared branch already proven on main is tracked through the existing read-only carried-commit path, without posting an unobserved old head for merge.

`ship` previously saved terminal shipped state before deploy/device prerequisites, and reset partial iOS state only after effects. It now computes a typed delivery state first and persists phase, pending deployments, device evidence and partial metadata together through the existing atomic Store write. `watch_deploys` no longer persists an empty pending queue before its completion proof. `mark_deployed` records proof and phase together, bound to the current commit; a pending iOS artifact remains pending after deployment. When its iOS build becomes installable, that same-commit deploy proof prevents needless requeueing. A later repair commit cannot reuse the proof. Existing explicit device confirmations survive partial/retried completion.

Bounded generation is not a formal proof.
- Pure bridge imports only the actual stdlib state module, under PATH-only environment, isolated Python, byte/event/response/time limits and external-access audit denial. It reports actual variants/payloads, never law verdicts. No implementation is cloned into the oracle.
- Python AST checks, two Bash installer syntax checks, TypeScript typecheck and patch application check pass; exact commands/durations/hashes are in `GATES.json`.

Controller tests use real Loop methods and real Store in fresh temporary directories with fake GH and effect edges. Python audit guards and the macOS sandbox deny networking, sensitive/live state reads and subprocesses. Cryptography is explicitly unavailable through fail-on-use import sentinels; these controller paths do not construct JWTs, and no JWT/signature implementation is replaced or claimed tested. The Config, Asc, GitHub, Cursor and Store classes, HTTP helpers, operator CLI main, gate/check_ship policy, follow-up inheritance, physical-device evidence classifier, deploy-kind mapping and request-deploy adapter are byte-identical source sections to baseline; hashes are retained. No feedback/account/message, real merge/tag/release, signing key, deployment or shared lock was accessed.

Existing legitimate records remain compatible, including legacy scalar pending_deploy at deployment completion. Approval timestamps emitted by the existing approve command remain accepted; malformed control values fail closed.
