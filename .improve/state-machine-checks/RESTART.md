# Planned restart ownership checks

Run `cd harness/arbos-pi-ext && node --test restart-state-laws.test.ts` with the normal pinned harness dependencies and existing Rust toolchain. The suite compiles a std-only bridge importing the actual `crates/arbos-relay/src/restart_lifetime.rs` reducer into a fresh temporary binary; no new Cargo crate/dependency or SDK is required. The child has a PATH-only environment, a temporary cwd, bounded typed records/output/time, and no effects or project configuration imports. Four Effect4 Schema-derived laws each run 256 seeded traces, with mandatory successful transitions, plus a protocol recovery test.

Run `cargo test --locked -p arbos-relay restart::ownership_regressions::` and `cargo test --locked -p arbos-relay a_planned_restart_waits_for_box_work` for the actual handler/guard/control tests. These use temporary synthetic relay states, real Tokio locks and task abort; no signals, live sockets, services, accounts, cloud providers, or deployment operations are needed.

For the actual-function negative control run `python3 .improve/state-machine-checks/check_restart_mutant.py --root . --out <private-output-directory>`. It copies only the reducer/bridge/law source into a private fixture, links existing dependencies read-only, and removes the actual reducer's generation guard on Release. The unmodified 256-case control must pass and the mutant must semantically falsify, shrink and deterministically replay. Input hashes must stay unchanged.

These finite cases are regression evidence, not a proof of all traces. Native tests cover handler/guard effects and cancellation without sending real signals; generated laws cover the real reducer. Full exact-source composition/CI remains separate. Successful planned requests retain their guard through the existing 90-second fallback; only a canceled exact owner may release early. Shutdown is terminal and cannot be thawed by an old planned guard or reset task. Pricing, device calibration, notice/drain durations and poll intervals are unchanged.
