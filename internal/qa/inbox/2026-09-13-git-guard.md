# For QA: git identity and base-branch guard (K-07)

From the features agent. Branch `cursor/git-guard-b027` → `rust`.

## What I am building

A check in front of every `bash` call, kernel-side, so the model cannot commit as the wrong person or land work on the wrong branch by accident:

- `git commit` in a directory whose git has **no** `user.name` or `user.email` is refused with the exact `git config` commands to fix it, unless the command sets an author itself (`--author=`, `-c user.email=`, `GIT_AUTHOR_EMAIL=`).
- `git push` straight to a **protected** branch (`main`, `master`, and the place's configured base) is refused: push a feature branch and open a PR. Explicit `--force` to a protected branch is refused too.
- `gh pr create` must name `--base`; when the place configures a base, a different `--base` is refused.
- Config, optional: `<place>/.arbos/git.toml` with `base = "rust"`, `protected = ["main", "rust"]`, `enabled = true`. Absent file: base unknown (so `gh pr create` just needs an explicit `--base`), protected = `main`, `master`. `enabled = false` turns the guard off for the place; `ARBOS_GIT_GUARD=off` in the kernel's environment does the same everywhere.
- The instance prompt gets one line: the base branch and the two rules, plus the standing rule from `main`'s prompt: never attribute a commit to an identity you have not confirmed with the user.

## How to exercise it

In a fresh repo with no `user.email`: `arbos-kernel run "commit README with message init"` → the tool result is the refusal; no commit. Then `git config user.email …` and again → commit. With `.arbos/git.toml` `base = "rust"`: ask for `gh pr create --base main …` → refused; `--base rust` → allowed (gh itself may still fail without auth). `git push origin main` → refused; `git push -u origin feature-x` → allowed.

## What could break — attack here

1. Bypasses: `git -C other/dir commit`, `cd x && git commit`, `sh -c 'git commit'`, `eval`, `git ci` alias, `command git commit`, `\git commit`, `GIT_DIR=… git commit`, a script file that commits. The parser is a tokenizer over `&&`/`;`/`|`/`||` segments; name what gets through.
2. False positives: `git commit --help`, `echo "git commit"` (quoted text), `git log --grep 'git push'`, `git push` to a non-protected branch with `refs/heads/main` in a refspec (`git push origin HEAD:main` **should** be refused; is it?), `git push --dry-run`.
3. `git commit` in a worktree child (PR #9 / #17): identity comes from the shared `.git`; refusals should match.
4. `git.toml` malformed → error on every bash call? It should log once and behave as absent.
5. Approval interplay: a command that needs approval *and* trips the guard: the guard must refuse before the user is asked.
6. Performance: `git config` runs once per `git commit` segment; a command with 50 `git commit` calls.
