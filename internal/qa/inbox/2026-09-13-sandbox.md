# P-07 sandboxing — QA note (features agent, 2026-09-13)

Branch `cursor/sandbox-b027`, base `rust`.

## What it does

`bash` commands run inside a sandbox when the place asks for it:

```toml
# .arbos/sandbox.toml
enabled = true                 # default false
network = false                # default true
allow_write = ["~/.cache", "~/.cargo/registry"]   # beyond the place and /tmp
```

Per agent: `sandbox: on|off` in `agent.md` overrides the place (`inherit` = the place's setting). Linux uses **bubblewrap** (`bwrap --ro-bind / / --dev /dev --proc /proc --tmpfs /tmp --bind <place> <place> [--bind p p …] [--unshare-net] --die-with-parent`); macOS uses **sandbox-exec** with a generated profile (allow default; deny `file-write*` except the place, `/tmp`, `$TMPDIR`, allow_write; deny `network*` when off). The whole filesystem stays readable; writes land only in the place, `/tmp` (a private tmpfs on Linux), and the listed paths.

Enabled but the tool is missing → the command **fails closed** with an install hint (`apt install bubblewrap`). The instance prompt says `Sandbox: on (no network)` so the model does not fight it. Job journals and exit files live under the place, so `await`/`jobs` are unchanged. `terminal` (the PTY) and plan `shell` nodes are **not** sandboxed yet (noted in the PR).

## Attack ideas

1. `bash: echo x > ~/evil` with the sandbox on: "Read-only file system"; `ls ~` still works.
2. `bash: curl https://example.com` with `network = false`: fails fast (no DNS); with `network = true` works.
3. `git commit` inside the place: works (`.git` is under the place; `~/.gitconfig` readable).
4. `cargo build` in a Rust place without `~/.cargo/registry` in `allow_write`: fails on registry writes — the default `allow_write` includes `~/.cache` and `~/.cargo/registry`; check `npm` (`~/.npm`) and `pip` (`~/.cache/pip`) too.
5. Symlink from the place to outside (`ln -s /etc/hosts x; echo > x`): the target is on the read-only bind → blocked.
6. `sudo`: no setuid in a user namespace → "effective uid is not 0"; fine.
7. Background jobs (`background:true`, servers): `--die-with-parent` kills the sandbox when the wrapper shell dies — check a detached job survives the tool call (the wrapper `sh` is the parent and stays).
8. A worktree child (#9/#17): its cwd is `.arbos/worktrees/<id>` — under the place, writable. Good; confirm.
9. `agent.md` `sandbox: off` on a child of a sandboxed parent: today the child's own line wins. Decide whether a parent should be able to force it on (like `restrict_allowlist`).
10. macOS: `sandbox-exec` prints a deprecation warning to stderr on some versions — must not pollute the tool result. Untested here (Linux VM).

## How to run

`printf 'enabled = true\nnetwork = false\n' > .arbos/sandbox.toml`; prompt "run bash: echo hi > ~/x.txt; echo hi > ok.txt; curl -m 3 https://example.com; ls" → the first write and the curl fail, `ok.txt` appears.
