# Goals held until met — PR #159, branch `cursor/goals-b027` (on `main`)

T3-01. `subscribe add kind=goal prompt="…" cmd="<check>" every="15m"`. First check runs at once; while it fails the agent is woken with the goal + check output (+ last time's output); exit 0 closes the goal, tells the agent ("Goal met") and the user (`goal met: …` line), `kernel.log` `goal_met`. No `cmd` → woken each period until `subscribe remove N`.

Scenarios:
- Benchmark item 9 shape: "keep CI on main green" with `cmd = gh run list --branch main --limit 1 --json conclusion -q '.[0].conclusion' | grep -q success`; break CI, watch the goal wake the agent within `every`; fix; watch it close.
- A goal set by a chat that is then archived/closed: the file lives under the agent's `subscriptions/`; if the agent is archived the goal goes with the folder (say if a goal should move to root on archive).
- `every = "10s"` → refused (floor 30 s). Missing `prompt` → refused.
- Strip/panel: shows as a subscription with "goal · every …"; `subscribe list` lists it.
- Restart while a goal is open: it keeps firing (file-based).
- Two goals with checks at once: `MAX_SHELL` in-flight cap shared with shell subscriptions.
